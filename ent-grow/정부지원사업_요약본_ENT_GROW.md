# 1. 문제 인식

## 1.1 사업 배경

K-pop 산업은 세계적으로 성장했지만, 그 가치는 **데뷔 이후**에 집중되어 있다. 음반·공연·굿즈·팬덤 플랫폼은 모두 데뷔한 아티스트를 전제로 작동한다. 반면 아티스트가 만들어지는 **데뷔 이전 3~7년**은 기록도, 데이터도, 팬도 없는 **암흑 구간**이다.

이 구간에는 세 종류의 이해관계자가 있지만, 이들을 연결하는 인프라는 존재하지 않는다.

| 이해관계자 | 규모(추정) | 현재 상태 |
|---|---|---|
| 아이돌을 꿈꾸는 연습생 | 5,000~10,000명 | 기록·피드백·팬 접점 없음 |
| 연습생을 응원하는 팬 | 50만~100만 명 | 데뷔 전 접점 자체가 없음 |
| 연습생을 스카우트하는 기획사 | 100~200개 | 관리·검증 도구 없음 |

## 1.2 문제 정의

**"연습생의 노력은 아무도 알아주지 않고, 성공 가능성은 아무도 모르고 있다."**

| 대상 | 문제 | 결과 |
|---|---|---|
| **연습생** | 매일 6~10시간 연습하지만 기록이 남지 않음. 사진·영상은 개인 폰과 메신저에 흩어져 유실 | 성장 확인 불가 → 자기효능감 저하 → 번아웃·이탈 |
| **팬** | 데뷔 전 연습생은 공식 채널이 없어 응원할 대상·방법·피드백이 모두 부재 | 초기 팬이 될 기회 상실, 팬덤 형성 지연 |
| **기획사** | 연습생 정보가 엑셀·카톡·개인 폰에 분산. 스카우트는 인맥과 감에 의존 | 검증 비용 증가, 스카우트 적중률 저하, 이탈 징후 감지 불가 |

## 1.3 기존 대안의 한계

| 대안 | 제공 가치 | 한계 |
|---|---|---|
| 위버스·버블 등 팬덤 플랫폼 | 데뷔 아티스트와 팬의 소통 | **데뷔 이후**만 커버. 연습생은 대상이 아님 |
| 유튜브·인스타그램·틱톡 | 노출과 팬 유입 | 기록·성장 데이터 없음. 소속사 관리 기능 없음 |
| 오디션 앱 | 공고·접수·투표 | 단발성 이벤트. 지속적 기록 없음 |
| 기획사 자체 엑셀·카톡 | 무료, 익숙함 | 분산·유실·검색 불가 |
| 연습생 개인 SNS | 자유로운 노출 | 권리·소속사 리스크, 데이터 축적 없음 |

**핵심 공백**: "기록"과 "팬덤"과 "스카우팅"을 동시에 다루는 서비스가 없다.

## 1.4 왜 지금인가

1. **프리데뷔 콘텐츠의 대중화** — 데뷔 전 연습생이 숏폼으로 화제가 되는 사례가 반복 등장
2. **팬덤 경제의 전면화** — 멤버십·후원·커머스가 주요 수익원으로 부상
3. **오디션·서바이벌 포맷의 상시화** — 지원자 풀이 커지고 사전 검증 수요 증가
4. **엔터 산업의 SaaS 전환** — 계약·정산·연습생 관리의 시스템화 진행
5. **AI 영상 분석의 저비용화** — 하이라이트 추출·자세 분석이 API 수준으로 저렴해짐

# 2. 실현 가능성

## 2.1 솔루션 개요

ENT GROW는 **기록 인프라**를 중심으로 3개 제품 레이어를 운영한다.

```
[GROW] 연습생 기록  →  [FAN] 팬 응원·후원  →  [PARTNER/SCOUT] 기획사 관리·스카우트
              ↑                    ↓                      ↑
              └──── EGI 성장지수 · 권한 기반 공개 ──────────┘
```

| 레이어 | 대상 | 핵심 기능 | 제공 가치 |
|---|---|---|---|
| **GROW** | 연습생 | 연습 일지, 사진·영상 보관, 스킬 트래킹, 성장 포트폴리오 | 노력의 증명 |
| **FAN** | 팬 | 공개 프로필, 성장 타임라인, 응원, 멤버십, 후원 | 참여형 팬 경험 |
| **PARTNER / SCOUT** | 기획사·스카우트 | 통합 관리, 성장 리포트, 검색·매칭, 오디션 운영 | 의사결정 비용 절감 |

## 2.2 핵심 기능 및 구현 계획

| 기능 | 구현 내용 | 기술 요소 | 목표 시점 |
|---|---|---|---|
| 연습 일지 | 일자별 연습 종류·시간·목표·컨디션 | 모바일 웹/PWA | 2027 Q1 |
| 미디어 보관 | 원본 화질 저장, 날짜·곡·파트 자동 태깅 | 오브젝트 스토리지, 메타데이터 | 2027 Q1 |
| 성장 포트폴리오 | 성장 곡선, 스킬 레이더, 마일스톤, PDF 출력 | 데이터 시각화, PDF 생성 | 2027 Q2 |
| EGI 성장지수 | 5개 요소 가중 합성 지수 | 통계 모델, 정규화 | 2027 Q4 |
| 팬 타임라인 | 공개 프로필, 성장 기록 열람 | 웹 프론트, 권한 엔진 | 2027 Q3 |
| 스카우트 검색 | 포지션·나이·스킬·EGI 필터 | 검색 인덱스, 추천 | 2028 Q2 |
| AI 하이라이트 | 영상 구간 자동 추출·태깅 | 영상 분석 API | 2029 |

## 2.3 기술 아키텍처 (개요)

| 계층 | 구성 | 비고 |
|---|---|---|
| 클라이언트 | 반응형 웹, PWA, 기획사 웹 대시보드 | 초기 앱 배포 비용 절감 |
| API | REST/GraphQL, 권한 기반 접근 제어 | 소속사·연습생·팬 역할 분리 |
| 데이터 | PostgreSQL(정형), 오브젝트 스토리지(미디어), 검색 인덱스 | 국내 리전 우선 |
| 분석 | EGI 배치 연산, 팬 반응 집계 | 개인 식별 정보 분리 |
| 미디어 | 트랜스코딩, 썸네일, 스트리밍 | CDN 연동 |
| 보안 | 암호화, 접근 로그, 보관 기한 자동 파기 | 개인정보보호법 대응 |

**개발 전략**: MVP는 검증된 범용 기술로 6개월 내 출시하고, AI 기능은 외부 API로 시작해 비용을 변동비화한다.

## 2.4 EGI (ENT GROW Index) 설계

| 구성 요소 | 가중치 | 측정 방식 |
|---|---|---|
| 성장률 | 30% | 스킬 평가 점수의 기간 대비 변화율 |
| 연습량 | 25% | 주간 연습 시간·일수 |
| 코치빌리티 | 20% | 트레이너 피드백 후 개선 정도 |
| 다양성 | 15% | 장르·포지션·콘텐츠 유형의 폭 |
| 팬 반응 | 10% | 응원·조회·후원의 정규화 지표 |

**설계 원칙**: 절대적 실력 순위가 아닌 **성장 가능성 지표**로 정의한다. 팬에게는 구간(band)으로만 노출하고, 원점수는 소속사에만 제공해 낙인 효과를 방지한다.

## 2.5 차별성

| 구분 | 기존 서비스 | ENT GROW |
|---|---|---|
| 대상 시점 | 데뷔 이후 | **데뷔 이전 + 이후** |
| 핵심 자산 | 콘텐츠·관계 | **축적된 성장 기록** |
| 기획사 가치 | 없음 | 관리 효율 + 스카우트 정확도 |
| 팬 가치 | 완성된 아티스트 소비 | **성장 서사에 참여** |
| 데이터 | 없음 | EGI 표준 지표 |

## 2.6 법·제도 대응 (사업 존속 리스크 관리)

| 항목 | 리스크 | 대응 |
|---|---|---|
| 개인정보보호법 | 미성년자 정보 수집·이용 | 법정대리인 동의, 최소 수집, 보관 기한 명시 |
| 초상권·저작권 | 사진·영상의 무단 공개·2차 이용 | 업로드 시 권리 동의, 소속사 승인 게이트 |
| 청소년보호 | 유해 콘텐츠·악성 댓글 | 연령 제한, 신고·차단, 댓글 필터 |
| 전자상거래·후원 | 결제·환불·표시광고 | PG 제휴, 약관·환불 정책 명시 |
| AI 기본법(2026 시행) | AI 활용 고지 의무 | AI 분석 사실 고지, 인간 최종 판단 |
| 생체정보 | 얼굴·음성 데이터 | **수집하지 않음**을 기본값으로 설계 |

> **3원칙**: 수집 최소화 · 공개 최소화 · 보관 기한 명시

**소속사 신뢰 확보 장치**: 모든 프로필은 소속사 승인 후 공개되며, 무단 스카우트를 금지하고 승인된 스카우트만 허용한다. 이는 최대 리스크인 "소속사의 반발"을 구조적으로 해소하는 설계다.
